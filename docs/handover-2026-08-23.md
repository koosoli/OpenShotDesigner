The 369 lint warnings are deliberate, not noise:
- ~114 `jsx-a11y/label-has-associated-control` — captions rendered as a `<label>`
  **sibling** of their control with no `htmlFor`, so screen readers announce
  those inputs unlabelled. A real defect, left as a warning because the honest
  fix is per-site and a codemod that wraps the control would inherit the
  caption's opacity and text size onto it in 114 places. **Good first task.**
- ~220 `no-explicit-any` / `no-unused-vars` — the pre-existing 129 `any` escapes
  plus unused type imports, warned so rule 5 ("no NEW any") has teeth without
  turning the build red on existing debt.

## Done this session

**Tooling and correctness**
- ESLint (flat config) with `react-hooks` and `jsx-a11y`; `exhaustive-deps` is an
  error. All 22 hook-dependency errors resolved: 12 were `?? []` fallbacks that
  made downstream memos recompute every render, one was a genuine stale closure
  in the quick-search Enter handler, and the canvas keyboard effect was missing
  five dependencies.
- `commitSetupState` merges per key against the state the caller read, so two
  setup writes in the same render no longer discard each other
  (`src/domain/plan/setupWrite.ts`).
- `createCameraAndShot` always returned `shotId: ''`; `duplicateCurrentSetup`
  gave the copy the original's element ids; `addElement` and six waypoint sites
  hand-rolled ids. All now use `createId` (rule 16).
- Referential integrity: `src/domain/integrity.ts` cascades truss, cue, circuit
  and source deletion; `removePerson` also clears task assignees and pick-ups.
- Storage: a project that fails to migrate is no longer indistinguishable from
  one that does not exist — the dashboard says what happened, and
  `writeProject` no longer stamps unmigratable data as current.
- Screenplay parser: cues only accepted a whitelist of extensions, so
  `JENNA (WHISPERING)` became ACTION and took its dialogue and the character's
  whole presence in the breakdown with it.
- Call sheets listed no cast unless screenplay **scenes** were scheduled; days
  scheduled by setup or shot now resolve cast through the actors on the plan
  (`src/domain/reports/dayCast.ts`).
- The global print stylesheet hid every `<header>`, which is the masthead of
  every printable report — that is why an attached logo never appeared.

**Performance**

## Things worth knowing before you start

- `node scripts/capture-screenshots.mjs` drives the installed Chrome over CDP
  (no dependency) and re-shoots the README gallery. A fresh profile means empty
  IndexedDB, so it captures the first-run project — which ships the full example
  production. `--only <slug>` for one shot; `call-sheet-print` renders under
  print-media emulation, which is how the masthead bug was caught.
- The example production is the test fixture people actually see. When adding a
  module, add example data for it in `src/utils/sampleContent.ts` —
  `src/utils/__tests__/sampleProject.test.ts` asserts every module has some.
- **Templates → Fill empty modules with examples** loads that data into an
  existing project, filling only what is empty.
- `docs/codebase-audit-2026-08-23.md` has the full findings list; items 1, 2, 4,
  5, 6 and 8 of its "open findings" are now closed.
- Still open from that audit: coverage cells outliving their cue is fixed, but
  the parser's dual-dialogue (`^`) and `I/E.` handling remains unverified, and
  `src/generated/fixture-db.json` is committed while
  `implementation-progress.md` still says its licensing review is pending —
