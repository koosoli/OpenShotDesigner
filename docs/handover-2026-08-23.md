## Done this session

  error. All 22 hook-dependency errors resolved: 12 were `?? []` fallbacks that

  `writeProject` no longer stamps unmigratable data as current.

  `JENNA (WHISPERING)` became ACTION and took its dialogue and the character's
  whole presence in the breakdown with it.

  scheduled by setup or shot now resolve cast through the actors on the plan

## Things worth knowing before you start

- `node scripts/capture-screenshots.mjs` drives the installed Chrome over CDP
  (no dependency) and re-shoots the README gallery. A fresh profile means empty
  IndexedDB, so it captures the first-run project — which ships the full example
  production. `--only <slug>` for one shot; `call-sheet-print` renders under
  print-media emulation, which is how the masthead bug was caught.
- The example production is the test fixture people actually see. When adding a
  module, add example data for it in `src/utils/sampleContent.ts` —
  `src/utils/__tests__/sampleProject.test.ts` asserts every module has some.
- **Templates → Fill empty modules with examples** loads that data into an
  existing project, filling only what is empty.
- `docs/codebase-audit-2026-08-23.md` has the full findings list; items 1, 2, 4,
  5, 6 and 8 of its "open findings" are now closed.

## Addendum — later session, 2026-08-23

**Shipped**

- **Headshot drag in every direction** — the scale is applied about the framing
  point (`transform-origin: x% y%`), which is what lets the short axis move at
  any zoom; `dragFraming` converts pointer pixels through the real travel and
  steps the zoom to `UNLOCK_ZOOM` when an axis has none. (A rotation control
  was built and removed in the same session: "tilt" meant vertical movement.)
- **Pick-ups on the person's row** — `CallSheetPerson.pickupTime/pickupLocation`,
  printed as a P/U column on the cast and crew tables. A pick-up overrides the
  derived cast filter the same way an individual call does. (The pick-up list
  itself already saved and printed; the "not working" was that nothing reached
  the performer's own line.)
- **Slugline groups on the shooting schedule** — `StripContext.slugline`
  (scenes: their heading; setups: synthesised from INT/EXT + location + time of
  day, or their own heading-shaped location text) and `sluglineHeaderBefore`,
  which opens a `Sc 3 · INT. LIVING ROOM - DAY` row on the first strip of a run.
- **Scene ↔ location linking in one control** — `SetLocationLink` on every
  scene heading in the editor, on the call-sheet editor's "Locations on this
  sheet", and on the script locations report. The link is an alias on the
  `Location` (`domain/locations/linking.ts`), which is what the breakdown
  already resolved by; `dayLocations.ts` and `stripContext.ts` resolve free text
  by name and alias too, so setups whose location field holds a whole heading
  follow the same link.
- **Scene numbering regimes** — `domain/script/numbering.ts`.
  `Project.sceneNumbersLocked`: AUTO renumbers by position on every edit;
  LOCKED keeps every number, names an insert 3A (3AA between 3A and 3B),
  leaves gaps on removal. Omitted headings keep their slot in both. The editor
  no longer stamps `prev + 1` on new headings (that produced duplicates); a
  toolbar lock toggle and an editable number when locked. Imported scripts
  carrying non-positional numbers lock on arrival.
- **Budget** — `domain/budget/`. `Person.rateCard` (amount; per day / per week
  pro-rated over `weekDays` / flat; optional `vatPercent`), `Project.budget`
  (settings with EUR + 17 % Luxembourg defaults, `equipmentRates` keyed by the
  master-list grouping `category:brand:model`, manual `lines`), `deriveBudget`
  with per-line cent rounding, VAT by rate, contingency, unpriced report, CSV.
  UI: `components/budget/BudgetPanel.tsx`, `RateCardFields` (also on the Crew
  form), new `budget` workspace module (profiles saved before it existed gain
  it on load if they show contacts).
- **Day needs** — `domain/reports/dayNeeds.ts`: per day, the setups (setup
  block, shot owners, scene-number match), scene numbers, cast via
  `castFilterForDay`, all crew on shooting days, peak equipment per setup;
  `countNeedDays` feeds the budget. UI: Budget → Day needs.

**Known limits worth saying out loud**

- Crew are assumed on every shooting day. A production with day players
  expresses it with a budget line; per-person availability is the obvious next
  step and `DayNeeds.crewPersonIds` is where it would land.
- Weekly rates pro-rate by the day. Productions that pay full weeks regardless
  should enter a flat fee; a "round up to whole weeks" option would be a
  one-line change in `rateNet`.
- A setup links to a script scene only by `sceneNumber`. Renaming a locked
  number by hand ("2" → "2A") detaches its setups until their number is edited
  to match — the same coupling the reports panel already has.
